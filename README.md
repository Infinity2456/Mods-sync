# ModSync (NeoForge 1.21.1)

Сервер при старте сам открывает отдельный TCP-порт синхронизации и раздаёт моды из своей папки `mods`.
Клиент **при запуске игры** (ещё до входа на сервер) обращается на адрес из своего конфига, получает список модов,
сравнивает по SHA-256 со своей папкой `mods`, докачивает недостающее, проверяет хэши и перезапускает игру.
В главном меню появляется экран ModSync с проверкой/прогрессом; если всё актуально - он сам исчезает.

Синхронизация идёт по собственному порту и никак не связана с сетью Minecraft, поэтому работает и тогда,
когда клиенту не хватает модов, без которых Minecraft не даст зайти на сервер.

## Возможности
- Сверка по хэшам, докачка недостающего, замена устаревших версий (старые файлы уходят в `modsync/backup/`).
- Докачка: если связь оборвалась, клиент сам переподключается (до 3 раз) и качает только недостающее; недокачанные файлы сохраняются между запусками.
- Окно загрузки: общий процент, объём, скорость и оставшееся время.
- Чёрный список (`server.removeMods`): моды, которые клиенты должны убрать, если они у них есть.
- Шифрование трафика, пароль-секрет, запоминание ключа сервера (как в SSH).
- Самообновление самого ModSync с проверкой подписи.

## Настройка

`config/modsync-common.toml` (на сервере и на клиенте один и тот же файл, значимы разные секции):

Сервер:
```toml
[server]
enabled = true
syncPort = 25566        # TCP-порт синхронизации - ОТКРОЙТЕ его в файрволе / пробросьте на роутере / в панели хостинга
bindAddress = ""        # пусто = все интерфейсы
secret = "мой-пароль"   # желательно задать, см. "Безопасность"
excludedMods = []
removeMods = []         # чёрный список: клиенты уберут эти моды (modId или имя файла), если они у них есть
```
Клиент:
```toml
[client]
serverAddress = "play.example.com:25566"   # host:port; порт можно опустить (по умолчанию 25566); пусто = выключено
secret = "мой-пароль"                      # должен совпадать с server.secret
```

## Сборка
1. Нужен JDK 21. Wrapper не приложен: выполните `gradle wrapper --gradle-version 8.10` (или скопируйте `gradlew`, `gradlew.bat`, `gradle/` из MDK NeoForge 1.21.1).
2. `./gradlew build` -> `build/libs/modsync-1.0.0.jar`
3. Положите один и тот же jar в `mods` на сервере и на клиенте.
4. Первый запуск создаст `config/modsync-common.toml` - заполните его (см. ниже).
5. Если версия NeoForge в `gradle.properties` недоступна - возьмите актуальную 21.1.x.

## Как решается "что отправлять"
- Отправляются все jar из `mods` сервера, кроме: списка `server.excludedMods` (modId или имя файла) и модов,
  у которых зависимость от neoforge/minecraft в `neoforge.mods.toml` помечена `side="SERVER"`.
- Конфиг: `config/modsync-common.toml`.

## Самообновление ModSync (протокол v1)
Сервер раздаёт два вида содержимого по одному порту:
- **Моды** - основной шифрованный протокол v2 (X25519 + AES-256-GCM).
- **Сам ModSync** - отдельный **замороженный протокол v1**, который никогда не меняется. Так клиент любой версии всегда может скачать
  новый ModSync, даже если протокол v2 когда-нибудь изменится (и не придётся обновлять мод вручную).

При запуске клиент сначала проверяет ModSync по v1: если на сервере лежит другая версия (`modsync-1.1.0.jar` вместо `modsync-1.0.0.jar`),
он скачивает её и сразу уходит на перезапуск, а моды синхронизирует уже новая версия. Новый jar кладётся в `mods`, а старый убирается в `modsync/backup/`
после закрытия игры (хелпер запускается из копии `modsync/helper.jar`), так что двух версий ModSync в `mods` одновременно не бывает.
В основной список модов jar ModSync не попадает. Если v1 недоступен (старый сервер, ошибка сети), самообновление пропускается без ошибки.
Отключить: добавьте `"modsync"` в `server.excludedMods`.

**Важно про безопасность v1:** этот протокол не шифрует трафик. Его целостность держится на `secret`: при заданном секрете манифест подписан HMAC-SHA256,
а jar сверяется по хэшу из подписанного манифеста. **Без секрета активный перехватчик может подсунуть чужой ModSync** (а это код, который запускается в игре),
поэтому для сервера с самообновлением секрет фактически обязателен.

## Чёрный список модов (`server.removeMods`)
Админ перечисляет моды (modId или имя файла), которые клиенты должны убрать, например читерские или конфликтующие:
`removeMods = ["xray", "badmod-1.0.jar"]`. Клиент находит такие файлы в своей `mods` и после закрытия игры **переносит их в `modsync/backup/`**
(не стирает), затем игра перезапускается. Исключения: сам ModSync никогда не удаляется, а мод, который сервер сам раздаёт, не удаляется,
даже если попал в список. Белого списка нет: всё, чего нет в чёрном списке и в раздаче сервера, остаётся у игрока как есть.

## Запоминание ключа сервера (как в SSH)
Сервер создаёт собственный ключ (`modsync/identity.key` рядом с сервером, **не отдавайте этот файл**) и подписывает им каждое соединение.
При первом подключении клиент запоминает отпечаток ключа в `modsync/known_servers.txt`. Если позже ключ изменился, синхронизация блокируется
с предупреждением «SERVER KEY CHANGED»: так заметна подмена сервера (в том числе когда `secret` не задан). Если админ действительно
переустановил сервер или сбросил ключ, на экране есть кнопка «Забыть старый ключ и повторить» (или удалите строку из `known_servers.txt`).
Отпечаток ключа сервер пишет в лог при старте: можно сообщить игрокам заранее. Для самообновления по v1 ключ сервера не используется - там работает подпись jar (ниже).

## Подписанные релизы ModSync
Самообновление по v1 идёт без шифрования, поэтому jar можно подписать (обычной подписью `jarsigner`), и клиент проверит, что новый ModSync
подписан **тем же ключом, что и уже установленный**. Подмена на чужой, неподписанный или изменённый после подписи jar отклоняется (в лог пишется предупреждение,
а моды при этом синхронизируются как обычно).

1. Один раз создайте ключ и храните его в тайне и в резервной копии:
   `keytool -genkeypair -alias modsync -keyalg RSA -keysize 3072 -validity 36500 -keystore modsync.jks`
2. Собирайте и подписывайте релиз: `./gradlew build signJar -PsignKeystore=modsync.jks -PsignAlias=modsync -PsignPass=пароль`
3. Выложите подписанный jar игрокам и на сервер. **Первую подписанную версию игроки ставят вручную**: от неё начинается доверие.
4. Режим `client.requireSignedSelfUpdate = true` вообще не принимает неподписанные обновления (по умолчанию `false`: пока установленный ModSync не подписан,
   обновление принимается по хэшу и секрету, как раньше).

Если потерять ключ, автообновление перестанет приниматься: придётся один раз заново поставить мод вручную (с новым ключом). Сроки действия сертификата не проверяются, сравнивается именно ключ.
Сборка с `signJar` в этой среде не запускалась (нет сети для Gradle) - проверьте у себя.

## Безопасность
Моды - исполняемый код, поэтому:
- Указывайте в `client.serverAddress` только сервер, которому доверяете. Отдельного подтверждения больше нет: адрес в конфиге и есть согласие.
- **Весь трафик шифруется всегда**: эфемерный обмен ключами X25519 (новые ключи на каждое соединение), данные в AES-256-GCM
  с проверкой подлинности каждого кадра - подслушать, подменить, переставить или обрезать данные по пути нельзя.
- **Задайте `server.secret` и такой же `client.secret`** (длинный случайный). Секрет подмешивается в ключи (PBKDF2 + HKDF) и сам по сети не передаётся.
  С ним сервер не отвечает ничего, пока клиент не докажет, что знает секрет, а клиент уверен, что говорит с настоящим сервером.
  Без секрета шифрование защищает только от пассивного прослушивания: активный перехватчик (MITM) может подсунуть чужой мод,
  а скачать моды может любой, кто видит порт.
- Размеры и имена файлов из манифеста проверяются, пути берутся только из белого списка имён, хэши сверяются.

## Докачка после обрыва
Недокачанные файлы лежат в `modsync/staging/<sha256>.part`. При обрыве связи во время загрузки клиент переподключается (до 3 попыток с паузой)
и просит у сервера только остаток файла (в запросе есть смещение). Если игру закрыли или сервер был недоступен, при следующем запуске (или по кнопке «Повторить»)
загрузка продолжится с того же места. Хэш всего файла проверяется в конце: если часть оказалась испорчена, она удаляется и файл скачивается заново.
Ненужные файлы в `staging` убираются автоматически.

## Обновления и перезапуск
- Новые файлы кладутся в `mods` сразу. Заменяемые/устаревшие версии (тот же modId) переносятся в `modsync/backup/`
  отдельным процессом после закрытия игры (Windows блокирует открытые jar).
- Игра перезапускается по её же командной строке. Если командную строку получить не удалось - показывается кнопка
  "Закрыть игру", запустите её вручную.
- Журнал хелпера: `modsync/helper.log`.
- Манифест на сервере строится один раз при старте сервера: после замены модов в `mods` перезапустите сервер.

## Известные ограничения
- Если сервер недоступен, показывается экран с ошибкой и кнопками "Повторить" / "Продолжить" (запуск игры не блокируется).
- Моды, уже загруженные игрой, обновляются только после перезапуска - поэтому он и нужен.
- Код не компилировался в среде NeoForge (только протокол клиент-сервер проверен отдельным локальным тестом) -
  возможны мелкие правки под вашу версию NeoForge.
